# VJudge 分页完整性与损坏缓存恢复设计

## 背景

VJudge `/status/data` 使用 `start`/`length` 窗口返回提交，`runId` 通常按降序排列，但 `time` 可能回跳，不能用时间判断分页边界。公开响应还包含 `recordsTotal` 与 `recordsFiltered`，当前接口样本将二者固定为 `9999999`，不能作为真实覆盖总量证明。查询结果按固定结果筛选枚举切片，但服务端没有提供可依赖的“所有状态已覆盖”证明。

本设计同时保证：页面结构或分页语义变化时不把不完整数据误报为完整；本地索引、分块或单条记录损坏时，新的合法响应仍可写入并按复合提交身份覆盖旧值。

## 目标与非目标

目标：

1. VJudge 不再使用 `time` 做排序、边界剪枝或停止条件。
2. 校验每个响应页内以及相邻页之间的 `runId` 严格递减，并拒绝重复/错位页。
3. 只有能够证明覆盖完整时返回 `coverage.complete=true`；基础窗口饱和且缺少可靠总量证明时保持 `partial`。
4. 单条坏记录、损坏索引、损坏分块不阻塞其它合法记录和新的合法响应；同一 `(accountId, judge, scope, submissionId)` 以最新合法数据为准。

非目标：

- 不猜测未知结果状态或伪造遗漏数量。
- 不恢复无法从损坏索引到达的旧分块；这些历史数据由后续合法抓取逐步补回。
- 不改变其它适配器已有的时间排序和边界语义。

## 方案

### 适配器分页

`fetchPage` 继续请求固定窗口 `length=100`。`fetchSlice` 请求 `start=0`，若第一页满页再请求 `start=100`；收集页时记录每页 `runId`。每条记录的 `runId` 必须是非空可解析标识，页内相邻值必须严格递减；第二页第一条必须严格小于第一页最后一条；所有已收集 ID 必须唯一。违反任一条件抛出 `OJMonitorError("schema-changed", ...)`，由 `fetchSubmissions` 返回失败结果，不把异常页面当作完整数据。

页面长度小于 100 时，切片未饱和且该切片完整。两页合计 200 条时，切片饱和，不能仅凭 `recordsFiltered=9999999` 声称读完。

### 完整性判定

- 基础 `all` 查询未饱和且结构校验通过：`ok`/`complete=true`。
- 基础查询饱和：按既有固定结果枚举抓取各切片，用于尽可能扩大已知下界；但即使每个切片都未饱和，也因为未知状态或服务端筛选语义没有可验证的穷尽证明，整体保持 `partial`。
- 任一切片饱和、响应结构异常或包含无法解析的单条记录：整体保持 `partial`；合法记录继续保留。
- `time` 只用于 `from`/`to` 统计窗口过滤，不参与顺序或是否停止分页的判断。

### 存储恢复

读取 envelope、索引或分块失败时按现有 fail-soft 规则返回空集合；真实 backend I/O 错误继续抛出。合并前过滤无法规范化的缓存记录。按 `buildSubmissionKey` 从所有可读分块移除 incoming 同身份旧值，再写入 incoming 所在月份分块并更新索引，使最新合法数据覆盖旧月份副本；损坏分块不会阻塞其它分块或 incoming 数据。

## 数据流与状态

1. 服务层对 VJudge 始终从统计窗口起点抓取，不传递或保存时间 resume boundary。
2. 适配器返回合法记录、覆盖状态和诊断（顺序异常、饱和切片、坏记录计数）。
3. 服务层保存当前状态；只有 `complete=true` 的状态成为 trusted 基线。
4. 存储层先 fail-soft 读取可用缓存，再以最新合法响应按复合身份 upsert。
5. UI 对 `partial` 展示已知下界，不把不确定数据显示为精确值。

## 错误处理

- 顶层响应缺少数组、`runId` 不可解析、页内/跨页顺序不严格或出现重复：`schema-changed`，保留已成功解析的记录并标记不完整。
- 单条记录字段损坏：跳过该条，合法记录保留，返回 `partial` 与坏记录计数。
- 基础窗口或结果切片饱和：继续已知切片抓取，但最终返回 `partial`，不猜测遗漏数。
- 本地 JSON/checksum/envelope/索引/分块损坏：按空值继续；backend 真实读写故障传播。

## 测试策略

- VJudge 页内 `runId` 非递减、跨页回跳、跨页重复：均验证 fail-closed。
- `time` 乱序但 `runId` 合法：验证不触发 schema-change，并验证仍按窗口过滤。
- 基础查询未饱和：验证 `ok`；基础查询饱和且所有已知切片未饱和：验证仍为 `partial`。
- 单条坏记录：验证合法记录保留且状态为 `partial`。
- 合法 submission-index 指向两个分块，其中一个分块 checksum 损坏：验证另一分块可读、新合法记录可写、坏分块不阻塞。
- 服务层不向 VJudge 传递或保存时间 boundary；版本、README、构建产物与 manifest 保持一致。
